# Event Ticketing Platform

A multi-role Laravel event ticketing platform with three separate portals (Customer, Organizer, and Admin), each with its own authentication guard and permissions, backed by a relational schema with database-level triggers and stored procedures for ticket/booking consistency.

## Features
- **Customers** browse events, book tickets, make payments, and view/cancel their own bookings
- **Organizers** create and manage their own events and view bookings for those events
- **Admins** manage all customers, organizers, events, and view platform-wide reports
- Each role authenticates independently (separate login flows and route groups per role)

## Tech Stack
- **Backend:** PHP, Laravel 12
- **Frontend:** Blade templates, Tailwind CSS, Vite
- **Database:** SQLite by default; schema includes custom migrations for indexes, functions/triggers, and stored procedures around event/ticket/booking consistency

## Architecture
Three role-scoped route groups (`customer.*`, `organizer.*`, `admin.*`) each run behind a `role:<guard>,<login-route>` middleware that checks the authenticated guard rather than a single shared `is_admin` flag. Controllers are namespaced per role (`App\Http\Controllers\Customer\BookingController`, `App\Http\Controllers\Organizer\{DashboardController,EventController}`, `App\Http\Controllers\Admin\{CustomerController,OrganizerController,EventController,DashboardController,ReportController}`), so each portal's logic stays isolated even though they share the same `Event`/`Booking`/`Ticket` models.

## Installation
```bash
composer install
npm install
cp .env.example .env
php artisan key:generate
php artisan migrate
npm run build   # or `npm run dev` for hot-reload during development
php artisan serve
```

## Environment Variables
Copy `.env.example` to `.env` and fill in the values for your setup. Key ones:
- `APP_KEY` — generated by `php artisan key:generate`, do not commit a real value
- `DB_CONNECTION` / `DB_DATABASE` (+ `DB_HOST`, `DB_USERNAME`, `DB_PASSWORD` if not using SQLite)

## Usage
- Visit `/` to browse events as a guest, or `/register` to create a customer account and book tickets.
- Organizers log in at `/organizer/login` to manage their own events and see bookings.
- Admins log in at `/admin/login` to manage customers, organizers, events, and view reports.

## Project Structure
```
app/Http/Controllers/
  Admin/          # CustomerController, OrganizerController, EventController, DashboardController, ReportController
  Organizer/      # DashboardController, EventController
  Customer/       # BookingController
  Auth/           # Separate auth controllers per role (Admin/Customer/Organizer)
app/Models/       # Booking, Customer, Event, Organizer, Payment, Ticket, User
resources/views/  # admin/, customer/, organizer/, events/, auth/
database/migrations/  # Schema, indexes, and DB-level functions/triggers/stored procedures
```
